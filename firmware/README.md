# Прошивка Voice-planner

Основной скетч: voice_planner/voice_planner.ino.
Плата: ESP32-S3-N16R8, микрофон INMP441, кнопка на GPIO4.
[Полная таблица подключения, включая дисплей](PINOUT.md).
Все GPIO заданы в voice_planner/board_pins.h.

## Настройка и загрузка

1. Установить пакет плат Espressif ESP32. Проверяемая версия — 3.3.12.
2. Открыть voice_planner/voice_planner.ino в Arduino IDE.
3. Если secrets.h ещё нет, скопировать secrets.example.h в secrets.h в той же папке.
   Уже подготовленный локальный secrets.h содержит прежние настройки Wi-Fi.
   Вписать имя сети 2,4 ГГц, пароль и адрес сервера:
   http://IP_КОМПЬЮТЕРА:8000/voice. Адрес 127.0.0.1 на ESP32 не подходит.
   secrets.h исключён из Git. Без него используются значения-заглушки.
4. Выбрать ESP32S3 Dev Module:
   - Flash Size: 16MB (128Mb);
   - PSRAM: OPI PSRAM;
   - Partition Scheme: 16M Flash (3MB APP/9.9MB FATFS);
   - при встроенном USB: USB Mode Hardware CDC and JTAG, USB CDC On Boot Enabled;
   - при USB-UART: USB CDC On Boot Disabled.
5. Выбрать порт платы, загрузить скетч, открыть Serial Monitor 115200.

Для Arduino CLI:

    arduino-cli compile --fqbn esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB,USBMode=hwcdc,CDCOnBoot=cdc firmware/voice_planner

Это конфигурация Serial через встроенный USB. При USB-UART заменить cdc на default
либо выбрать настройки в Arduino IDE.

## Поведение

- После включения отпустить кнопку, затем удерживать для записи.
- Отпускание завершает запись и запускает отправку WAV в теле POST /voice.
  Сервер возвращает номер задания, облако обрабатывает его в фоне.
- Формат: PCM16, mono, 16 кГц. Минимальная длительность — 0,2 с.
- С доступной PSRAM лимит 30 с. Без неё скетч пытается выделить буфер на 4, 3 или 2 с.
  Лимит печатается в Serial; для проверки 30 с нужна включённая OPI PSRAM.
- При заполнении буфера новые отсчёты не сохраняются. Отпустить кнопку для отправки.
- Wi-Fi подключается в фоне и восстанавливается при потере связи.
  Для передачи прошивка дополнительно ждёт сеть до 8 с.
- Без сети запись доступна. При ошибке передачи WAV остаётся в RAM:
  английская r в Serial повторяет отправку.
- Новое удержание заменяет неотправленную запись. Перезапуск очищает RAM.
- Во время ожидания сети и HTTP опрос кнопки блокируется; для следующей записи
  нужно отпустить кнопку. Короткие нажатия во время передачи не записываются.
- Повтор после потери ответа может создать дубликат на сервере.
- LED1: запись / передача. LED2: подключение к Wi-Fi.
- Дисплей показывает состояния и таблицу задач; распознавание выполняется на сервере
  через облачный сервис. Измерение батареи пока не реализовано.

## Первая проверка на устройстве

1. Собрать сигнальные соединения по PINOUT.md при отключённом питании.
2. Запустить сервер по инструкции ../server/README.md.
3. Проверить IP компьютера командой ipconfig и вписать его в secrets.h.
4. ESP32 и сервер подключить к одной доступной локальной сети.
5. После загрузки увидеть в Serial лимит 30 с и сообщение о подключении Wi-Fi.
6. Записать фразу 2–5 с, отпустить кнопку.
7. Проверить HTTP: 200 и прослушать новый WAV из server/recordings.
8. Проверить короткое нажатие, длинную запись и повтор r после недоступности сервера.

Если пик равен нулю — проверить SD, L/R, питание и выбранный канал.
Если слышен хрип и много клиппинга — уменьшить MIC_GAIN с 4 до 2 или 1.
Если сервер отвечает на компьютере, но ESP32 его не видит — проверить LAN-адрес,
доступ к TCP 8000 через брандмауэр и изоляцию Wi-Fi-клиентов.

## Экран состояний

| Надпись | Значение |
| --- | --- |
| CONNECTING | Ожидание Wi-Fi |
| READY | Можно удерживать кнопку и говорить |
| RECORDING | Запись идёт; отпускание отправляет файл |
| BUFFER FULL | Лимит записи достигнут; отпустить кнопку |
| SENDING | Ожидание сети или передача WAV |
| PROCESSING | Облако распознаёт речь и создаёт задачи |
| Таблица | Список дел получен с сервера |
| ERROR | Ошибка сети, сервера, I2S или памяти; подробности в Serial |

Используется шрифт из теста дисплея, поэтому надписи пока на английском.
На экране также указан фактический лимит записи.
ROTATE_180 = true в status_display.cpp разворачивает изображение на 180 градусов
относительно предыдущей рабочей версии. Чтобы вернуть прежнюю ориентацию, установить
ROTATE_180 = false. MIRROR_X / MIRROR_Y оставлены для коррекции панели, их менять не нужно.

При включении выполняется одна полная очистка для создания базового кадра.
CONNECTING, READY, RECORDING, BUFFER FULL и SENDING затем обновляются частично.
После окончания записи выполняется полное обновление итогового состояния
(таблица задач, ошибка отправки/облака или TOO SHORT); во время SENDING и PROCESSING очистка откладывается.
Запрос сохраняется в счётчике завершённых записей, поэтому замена кадров в очереди
не отменяет необходимую очистку. Если уже началась следующая запись, очистка
откладывается до её окончания.

Используется дифференциальный режим панели: в контроллер передаются полный новый
и предыдущий буферы, но промежуточные состояния выводятся частичной формой обновления
0xFF вместо полного цикла 0xF4. Эти режимы взяты из примера Good Display
GDEM035T81, функций EPD_SetRAMValue_BaseMap / EPD_Dis_PartAll.
Перед частичным обновлением старый кадр восстанавливается в RAM 0x26.
После каждого кадра панель уходит в deep sleep. Минимальная пауза после кадра — 300 мс.

В примере производителя рекомендована полная очистка после пяти частичных обновлений.
Поэтому до следующего завершения записи выполняется не более пяти частичных кадров.
Если сеть многократно переподключается без новых записей, дальнейшие промежуточные
кадры пропускаются до очистки. Это сохраняет правило «не мигать посреди записи».
Небольшие остаточные следы частичного обновления возможны до полной очистки.
Дисплей работает в отдельной FreeRTOS-задаче на ядре 0, а запись — в основном цикле.
Очередь хранит последнее состояние: короткое SENDING может смениться PROCESSING до
отрисовки. Экран не является мгновенным индикатором; LED1 реагирует сразу.
Во время обновления дисплея запись и опрос кнопки продолжаются.
Уже запущенный полный цикл не прерывается: если начать новую запись сразу после
предыдущей, её начало может совпасть с завершением очистки предыдущего кадра.
При ошибке BUSY дисплей отключается до перезапуска, RES удерживается LOW;
аудиотракт продолжает работать, ошибка видна в Serial.

### Проверка после сборки устройства

1. Загрузить прошивку с OPI PSRAM, увидеть в Serial лимит 30 с.
2. Дождаться READY и проверить, что текст развёрнут на 180 градусов относительно
   прежней версии. Полное мигание при включении ожидаемо.
3. Удерживать кнопку 5–10 с: LED1 должен загореться сразу, затем появится RECORDING.
4. Во время RECORDING не должно быть полного бело-чёрного мигания.
   Отпустить: дождаться HTTP: 200, PROCESSING и таблицы задач. Облако предварительно
   настраивается по server/CLOUD_SETUP.md. Без ключа ожидается CLOUD NOT SET,
   WAV остаётся на сервере. В Serial
   промежуточные кадры отмечены EPD: PARTIAL refresh, итог — EPD: FULL refresh.
5. Открыть последний WAV в server/recordings и проверить, что начало и конец
   фразы сохранены, а при обновлении экрана нет провалов звука.
6. Остановить сервер, записать фразу: после тайм-аута ожидается ERROR / UPLOAD FAILED.
   Запустить сервер и отправить r через Serial: ожидаются PROCESSING и таблица.
7. Проверить запись до лимита: BUFFER FULL, затем отпускание и отправка.
8. При выключенном питании отсоединить дисплей и повторить аудиотест:
   ошибка BUSY должна отключить только экран. Подключать обратно без питания.

## Облачный планировщик

Настройка: [server/CLOUD_SETUP.md](../server/CLOUD_SETUP.md).
API-ключ находится только на сервере, в secrets.json.
ESP32 продолжает отправлять WAV и запрашивает /jobs/{id}?compact=true в отдельной
задаче HTTP, не блокируя аудиозапись. После обработки получает /display/frame.bin:
кириллицу и переносы строк рисует сервер, дисплей получает готовые пиксели.

На странице шесть задач. Команда n в Serial Monitor переключает страницу.
Без новых записей список проверяется раз в 15 секунд. Пока идёт запись, сетевые
результаты сохраняются в очереди и не заменяют RECORDING на экране.
r повторяет только неудачную передачу WAV. Повтор облачного разбора выполняется
явно через POST /jobs/{id}/retry на сервере; ESP32 продолжит следить за этим заданием.
X-Recording-Id сохраняется при повторной передаче одного WAV для защиты от дубликатов.

Старый сервер, который только сохранял WAV без job_id, не поддерживает новую таблицу.
После обновления прошивки нужно также обновить сервер и настроить облачный ключ.
Поворот 180 градусов и режимы частичного/полного обновления сохранены.

## Исправления проверки кода 10.11.2026

- Ответ HTTP 200 принимается только с корректными status, job_id и processing.
  При неверном подтверждении показывается BAD SERVER ACK, WAV остаётся в RAM для r.

- Запоздалые события закрытого задания не заменяют актуальный экран.

## Голосовые команды управления

Удаление и выполнение распознаются на сервере тем же способом, что добавление:
удержать кнопку, произнести полную команду, отпустить.
Примеры — в [инструкции облака](../server/CLOUD_SETUP.md#голосовое-управление-делами).
Для этого серверного обновления перезагрузка прошивки не требуется.
Номер дела виден перед названием. Если внизу показано «? Повторите команду с №»,
записать новую полную команду, например «Удали задачу номер пять».
