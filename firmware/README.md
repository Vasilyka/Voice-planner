# Прошивка Voice-planner

Основной скетч: voice_planner/voice_planner.ino.
Плата: ESP32-S3-N16R8, микрофон INMP441, кнопка на GPIO4.
[Полная таблица подключения, включая дисплей](PINOUT.md).
Все GPIO заданы в voice_planner/board_pins.h.

## Настройка и загрузка

1. Установить пакет плат Espressif ESP32. Проверяемая версия — 3.3.12.
2. Открыть voice_planner/voice_planner.ino в Arduino IDE.
3. Скопировать secrets.example.h в secrets.h в той же папке.
   Вписать имя сети 2,4 ГГц, пароль и адрес сервера:
   http://IP_КОМПЬЮТЕРА:8000/voice. Адрес 127.0.0.1 на ESP32 не подходит.
   secrets.h исключён из Git. Без него используются значения-заглушки.
4. Выбрать ESP32S3 Dev Module:
   - Flash Size: 16MB (128Mb);
   - PSRAM: OPI PSRAM;
   - Partition Scheme: 16M Flash (3MB APP/9.9MB FATFS);
   - при встроенном USB: USB Mode Hardware CDC and JTAG, USB CDC On Boot Enabled;
   - при USB-UART: USB CDC On Boot Disabled.
5. Выбрать порт платы, загрузить скетч, открыть Serial Monitor 115200.

Для Arduino CLI:

    arduino-cli compile --fqbn esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB,USBMode=hwcdc,CDCOnBoot=cdc firmware/voice_planner

Это конфигурация Serial через встроенный USB. При USB-UART заменить cdc на default
либо выбрать настройки в Arduino IDE.

## Поведение

- После включения отпустить кнопку, затем удерживать для записи.
- Отпускание завершает запись и запускает отправку WAV в теле POST /voice.
- Формат: PCM16, mono, 16 кГц. Минимальная длительность — 0,2 с.
- С доступной PSRAM лимит 30 с. Без неё скетч пытается выделить буфер на 4, 3 или 2 с.
  Лимит печатается в Serial; для проверки 30 с нужна включённая OPI PSRAM.
- При заполнении буфера новые отсчёты не сохраняются. Отпустить кнопку для отправки.
- Wi-Fi подключается в фоне и восстанавливается при потере связи.
  Для передачи прошивка дополнительно ждёт сеть до 8 с.
- Без сети запись доступна. При ошибке передачи WAV остаётся в RAM:
  английская r в Serial повторяет отправку.
- Новое удержание заменяет неотправленную запись. Перезапуск очищает RAM.
- Во время ожидания сети и HTTP опрос кнопки блокируется; для следующей записи
  нужно отпустить кнопку. Короткие нажатия во время передачи не записываются.
- Повтор после потери ответа может создать дубликат на сервере.
- LED1: запись / передача. LED2: подключение к Wi-Fi.
- Дисплей удерживается в сбросе; измерение батареи и распознавание речи пока не реализованы.

## Первая проверка на устройстве

1. Собрать сигнальные соединения по PINOUT.md при отключённом питании.
2. Запустить сервер по инструкции ../server/README.md.
3. Проверить IP компьютера командой ipconfig и вписать его в secrets.h.
4. ESP32 и сервер подключить к одной доступной локальной сети.
5. После загрузки увидеть в Serial лимит 30 с и сообщение о подключении Wi-Fi.
6. Записать фразу 2–5 с, отпустить кнопку.
7. Проверить HTTP: 200 и прослушать новый WAV из server/recordings.
8. Проверить короткое нажатие, длинную запись и повтор r после недоступности сервера.

Если пик равен нулю — проверить SD, L/R, питание и выбранный канал.
Если слышен хрип и много клиппинга — уменьшить MIC_GAIN с 4 до 2 или 1.
Если сервер отвечает на компьютере, но ESP32 его не видит — проверить LAN-адрес,
доступ к TCP 8000 через брандмауэр и изоляцию Wi-Fi-клиентов.

## Дальнейшие этапы

Сначала подтвердить реальную запись, передачу и качество звука, включая работу PSRAM.
Затем добавить в эту прошивку драйвер дисплея на уже зарезервированных GPIO и вывод
состояний: подключение, запись, отправка, ошибка.
После этого подключить на сервере распознавание речи, определить формат задачи
и ответ ESP32, затем вывести задачи на экран.
Отдельный этап — проверка питания от аккумулятора и работы в закрытом корпусе.
