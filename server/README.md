# Локальный сервер

Рабочая точка входа — main.py. Сервер принимает WAV от firmware/voice_planner,
проверяет формат и сохраняет записи на диске. Распознавание речи пока не подключено.
Существующий server_v1.py оставлен без изменений; для запуска используется main.py.

## Установка и запуск

Из корня репозитория:

    py -m venv server/.venv
    & ./server/.venv/Scripts/python.exe -m pip install -r server/requirements.txt
    & ./server/.venv/Scripts/python.exe -m uvicorn main:app --app-dir server --host 0.0.0.0 --port 8000

Либо с зависимостями, установленными в текущем Python:

    py -m pip install -r server/requirements.txt
    & ./server/start_server.ps1

Окно сервера оставить открытым. Остановка — Ctrl+C.
Проверка на компьютере: http://127.0.0.1:8000/health.
Для ESP32 использовать LAN-адрес компьютера из ipconfig, например:
http://192.168.1.100:8000/voice. При смене IP изменить secrets.h и перепрошить.

Сервер предназначен для доступной локальной сети. Компьютер и ESP32 должны видеть
друг друга; при необходимости разрешить входящие подключения на TCP 8000.

## API

| Запрос | Поведение |
| --- | --- |
| GET /health | Состояние сервера и поддерживаемый аудиоформат |
| POST /voice, Content-Type: audio/wav | Приём WAV целиком в теле запроса |
| POST /voice, Content-Type: application/json | Совместимость с ранними JSON-задачами |
| GET /tasks | Последние 10 JSON-задач |

Аудио: WAV, PCM16, mono, 16000 Hz, от 0,2 до 30 с. Размер тела — до 1 000 000 байт.
Ответ при сохранении: status, file, seconds, bytes. Имя файла генерирует сервер.

Записи находятся в server/recordings, база JSON-задач — в server/tasks.db,
независимо от текущей рабочей папки. Эти файлы исключены из Git.
Приём WAV не создаёт задачу и не возвращает распознанный текст.
Каждый успешный POST создаёт отдельный файл, в том числе при повторе той же записи.

Ошибки: 400 — неверный WAV, длительность или JSON; 413 — превышение размера;
415 — неподдерживаемый Content-Type.

## Проверки

Нужны g++ в PATH и Python с зависимостями сервера:

    & ./server/run_checks.ps1

С Python из виртуального окружения:

    & ./server/run_checks.ps1 -Python ./server/.venv/Scripts/python.exe

C++-проверка использует audio_format.h из основной прошивки и создаёт тестовый WAV.
Четыре HTTP-теста проверяют приём WAV, сохранение без изменений, границы длительности,
повреждённые файлы, ограничения запросов и совместимость JSON/SQLite.
Сервер тестов запускается временно на свободном локальном порту и останавливается.
Тестовые базы и записи создаются в server/.build, рабочие записи не затрагиваются.
