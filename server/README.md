# Локальный сервер Voice-planner

[Подключение облака и первый запуск](CLOUD_SETUP.md).

Сервер принимает WAV от ESP32, сохраняет его, затем через Yandex SpeechKit получает
текст и через YandexGPT извлекает команды создания, удаления, выполнения и восстановления. Обработка идёт в фоне;
ESP32 опрашивает статус и получает готовую таблицу с кириллицей.
Для облачной части нужен ключ, который хранится только в server/secrets.json.
Без ключа WAV сохраняется, а состояние задания — needs_configuration.

## Запуск из корня репозитория

    py -m pip install -r server/requirements.txt
    & ./server/start_server.ps1

Остановка: Ctrl+C. Сервер предназначен для доступной локальной сети.
Компьютер и ESP32 должны видеть друг друга; в secrets.h на ESP32 указан LAN-адрес
компьютера, а не 127.0.0.1. Ключ облака в прошивку не переносится.

Для отдельного окружения:

    py -m venv server/.venv
    & ./server/.venv/Scripts/python.exe -m pip install -r server/requirements.txt
    & ./server/.venv/Scripts/python.exe -m uvicorn main:app --app-dir server --host 0.0.0.0 --port 8000

## API

| Запрос | Назначение |
| --- | --- |
| GET /health | Состояние сервера и наличие настроек облака |
| POST /voice, audio/wav | Сохранить WAV, получить job_id и processing |
| GET /jobs | Последние 20 заданий с ошибками и результатами |
| GET /jobs/{id} | Статус, текст и задачи одной записи |
| GET /jobs/{id}?compact=true | Короткий статус для ESP32 |
| POST /jobs/{id}/retry | Явно повторить неудачную обработку или начать после настройки ключа |
| GET /planner.json | Общий список задач в UTF-8 |
| GET /display/frame.bin?page=0 | Готовый 1-битный кадр 184 × 384, 8832 байта |
| POST /voice, application/json | Ранний режим JSON-задач, сохранён для совместимости |
| GET /tasks | Последние 10 задач раннего JSON-режима |

Новая таблица использует /planner.json. Старые записи раннего JSON-режима не
переносятся автоматически и не смешиваются с задачами, созданными из диктовки.

WAV: PCM16, mono, 16000 Hz, от 0,2 до 30 с; тело до 1 000 000 байт.
Ответ POST /voice подтверждает только сохранение файла. Создание задач подтверждается
state=done у задания. При неверном ключе или ошибке модели задачи не добавляются.

Все данные сохраняются относительно server, независимо от рабочей папки:
recordings/*.wav и *.json, data/planner.json, tasks.db.
SQLite — основной источник данных; JSON-файл общего списка обновляется после обработки.
Не запускать несколько экземпляров сервера с общей базой.

## Проверки

    & ./server/run_checks.ps1

С собственным интерпретатором:

    & ./server/run_checks.ps1 -Python ./server/.venv/Scripts/python.exe

Проверки используют отдельные временные базы, подменяют облачные ответы и не расходуют
баланс. Существующий server_v1.py сохранён без изменений; рабочая точка входа — main.py.

## Управление делами

Примеры: «Удали задачу купить хлеб», «Отмени последнее добавленное дело»,
«Лабораторная по физике выполнена», «Верни задачу номер пять»,
«Отмени последнее удаление».
Номера дел постоянные и показаны в таблице. При совпадении нескольких дел сервер
показывает запрос уточнения и ждёт новой полной команды с номером.

Удалённые и выполненные дела остаются в archived_tasks в /planner.json;
активные — в tasks. Схема экспорта — версия 2. Миграция существующей базы
автоматическая, исходные данные не удаляются. Подробнее — CLOUD_SETUP.md.

Для очистки всей активной таблицы: «Удали все события», «Удали все дела» или «Удали всё».
Это мягкое удаление всех pending-дел; выполненные и архив сохраняются.
В промпте и схеме используется action=del. Подробности — CLOUD_SETUP.md.
