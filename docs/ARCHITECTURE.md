# Архитектура

## Ранние отдельные тесты

Аудио: INMP441 → I2S → ESP32-S3 → WAV в RAM → HTTP POST /voice →
FastAPI → файл на диске.

Дисплей: кнопка → ESP32-S3 → кадровый буфер 8832 байта → SPI →
DESPI-C02 → GDEM035T81.

I2S выдаёт два 32-битных слота. Из выбранного канала формируется моно PCM16
с усилением и ограничением амплитуды. Заголовок WAV создаётся перед отправкой.
Сервер принимает WAV от 0,2 до 30 с и сохраняет без распознавания.

Дисплей выводит счётчик и четыре рисунка. Используются полное обновление,
контроль перехода BUSY в HIGH и тайм-аут завершения. После кадра панель засыпает.

Оба теста используют кнопку GPIO17 и загружаются отдельно.
Общая аппаратная схема может иметь другие GPIO.

## Общая цепочка

Голосовая команда → запись → сервер → распознавание речи → текст задачи →
хранилище задач → ответ ESP32 → список на e-paper.

Формат задач и серверная обработка описаны ниже. Аппаратную часть питания
и размещение в корпусе нужно проверить отдельно.

## Основная прошивка

В firmware/voice_planner собран аудиотракт под общую схему:
INMP441 SCK/WS/SD = GPIO12/13/14, кнопка GPIO4, LED1/LED2 = GPIO17/16.
Сервер запускается из server/main.py и сохраняет WAV в server/recordings.

Дисплею выделены GPIO11/10/9/21/8/6 (BUSY/RES/DC/CS/SDI/SCK).
Состояния выводятся отдельной задачей FreeRTOS через очередь последнего состояния.
Обновление дисплея не блокирует запись; таблица приходит готовым кадром от сервера.
GPIO5 зарезервирован под батарейный делитель. Полная распиновка — firmware/PINOUT.md.

## Облачное создание задач

POST /voice сохраняет WAV и создаёт voice_job в SQLite. Фоновый обработчик отправляет
PCM без WAV-заголовка в SpeechKit, затем текст и время записи — в YandexGPT с JSON Schema.
Pydantic проверяет структуру и календарные значения. Задачи сохраняются атомарно в
planner_tasks, после чего обновляются JSON рядом с WAV и server/data/planner.json.

ESP32 получает job_id, опрашивает статус в отдельной задаче и скачивает 1-битный кадр
184 × 384 с /display/frame.bin. Сервер формирует кириллицу и шесть строк на страницу.
В JSON сохраняется полный текст, в таблице — сокращение при нехватке места.
Модель не получает инструментов работы с файлами или базой, только текст и схему.

Без ключа WAV сохраняется, но state=needs_configuration. Проверки используют подменённый
транспорт облака; реальную точность, доступность аккаунта и качество отображения
этой версии ещё нужно проверить после настройки ключа и загрузки прошивки.

## Управление статусами дел

Облачная модель возвращает CommandBatch, сервер проверяет селекторы и применяет команды
в транзакции вместе с task_events и результатом voice_job.
Делам присваиваются постоянные номера. status=pending выводится в таблице,
done/deleted сохраняются в archived_tasks. Уточнения передаются в JSON и строку
уведомления на кадре. Повтор старого задания ограничен порядком записей и не
перезаписывает более новые изменения. Для этого этапа прошивка не меняется.
