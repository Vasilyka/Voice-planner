# Архитектура

## Реализованные прототипы

Аудио: INMP441 → I2S → ESP32-S3 → WAV в RAM → HTTP POST /voice →
FastAPI → файл на диске.

Дисплей: кнопка → ESP32-S3 → кадровый буфер 8832 байта → SPI →
DESPI-C02 → GDEM035T81.

I2S выдаёт два 32-битных слота. Из выбранного канала формируется моно PCM16
с усилением и ограничением амплитуды. Заголовок WAV создаётся перед отправкой.
Сервер принимает WAV от 0,2 до 30 с и сохраняет без распознавания.

Дисплей выводит счётчик и четыре рисунка. Используются полное обновление,
контроль перехода BUSY в HIGH и тайм-аут завершения. После кадра панель засыпает.

Оба теста используют кнопку GPIO17 и загружаются отдельно.
Общая аппаратная схема может иметь другие GPIO.

## План объединения

Голосовая команда → запись → сервер → распознавание речи → текст задачи →
хранилище задач → ответ ESP32 → список на e-paper.

Предстоит определить формат ответа, обработку ошибок и поведение без сети.
Нужно согласовать окончательную распиновку, питание и размещение в корпусе.

## Основная прошивка

В firmware/voice_planner собран аудиотракт под общую схему:
INMP441 SCK/WS/SD = GPIO12/13/14, кнопка GPIO4, LED1/LED2 = GPIO17/16.
Сервер запускается из server/main.py и сохраняет WAV в server/recordings.

Дисплею выделены GPIO11/10/9/21/8/6 (BUSY/RES/DC/CS/SDI/SCK).
Основная прошивка пока удерживает RES в LOW; вывод состояний и задач — следующий этап.
GPIO5 зарезервирован под батарейный делитель. Полная распиновка — firmware/PINOUT.md.
