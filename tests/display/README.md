# Тест e-paper-дисплея

ESP32-S3 + GDEM035T81 (SSD1685, 184 × 384) + DESPI-C02.
Скетч: ESP32S3_Display_Button_Test/ESP32S3_Display_Button_Test.ino.
Сторонние библиотеки не нужны: используются Arduino и SPI из пакета ESP32.
Последовательность обновления основана на примере Good Display.

## Подключение

Все соединения выполнять без питания. DESPI питается от **3,3 В**.
Переключатель P3 / RESE — **2.2** (2,2 Ом).

| Контакт DESPI-C02 | ESP32-S3 |
| --- | --- |
| BUSY | GPIO7 |
| RES / RST | GPIO8 |
| D/C / DC | GPIO9 |
| CS | GPIO10 |
| SCK / CLK | GPIO12 |
| SDI / DIN | GPIO11 |
| GND | GND |
| 3.3V / VCC | 3V3 |

Порядок подписей гребёнки DESPI: **BUSY, RES, D/C, CS, SCK, SDI, GND, 3.3V**.
Сверять с надписями конкретной платы. MISO не используется.
PREVGH, PREVGL, VCOM и RESE не подключаются к GPIO.

Кнопка: GPIO17 — кнопка — GND, внутренняя подтяжка INPUT_PULLUP.
У четырёхножечной кнопки выбирать контакты, замыкающиеся только при нажатии.

Шлейф панели подключается при открытой защёлке и отключённом питании.
В использованном экземпляре контакты шлейфа направлены вверх, к чёрной защёлке.
Ориентацию сверять с конструкцией разъёма; после установки закрыть защёлку.

## Запуск

1. Открыть скетч, выбрать ESP32S3 Dev Module и COM-порт.
   Исходная сборка проверялась с Arduino-ESP32 3.3.12. PSRAM не требуется.
2. Для Serial через встроенный USB включить USB CDC On Boot;
   при USB-UART использовать соответствующий порт и UART Serial.
3. Загрузить скетч, открыть Serial Monitor 115200.
4. При старте идут белый кадр, чёрный кадр и тестовая страница.
5. После READY нажимать кнопку: счётчик увеличивается, рисунки меняются.

Полные обновления сопровождаются мерцанием. Между ними выдерживается не менее 2 с.
Короткое нажатие во время блокирующего обновления может пропасть.
Удержание не даёт автоповтора, антидребезг — 40 мс. Счётчик хранится в RAM.
После кадра дисплей уходит в deep sleep, ESP32 продолжает опрос кнопки.

MIRROR_X = true компенсирует наблюдавшуюся зеркальность.
MIRROR_Y = false; параметры можно изменить в начале скетча.

## Диагностика

- no BUSY HIGH after refresh command: проверить BUSY, SPI, питание и FPC.
- BUSY остаётся HIGH 30 с: проверить питание, сброс и соединения.
- BUSY переключается, но картинки нет: проверить FPC и RESE=2.2.
- Счётчик меняется сам: проверить кнопку и общий GND.

После ошибки обновления останавливаются, RES удерживается LOW.
Исправить соединения без питания и перезапустить.
